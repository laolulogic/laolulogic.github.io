The most dangerous automation isn't the one that throws an error. It's the one that says "success" while leads quietly stop arriving. I fix broken automations every week; these are the causes I see most, and how to catch them.

Why automations break

  1. Expired connections: someone changes a password and the app disconnects.
  2. Changed fields: a form field is renamed and the data stops mapping.
  3. Required fields: the CRM rejects a record because a field is missing.
  4. API changes: an app updates and an old step stops working.
  5. Plan limits: a task or operation limit is reached and runs are held.
  6. Silent filters: a filter that no longer matches anything.

In one project, a Zapier plan had frozen and 37 leads were held. I diagnosed it, fixed the plan and replayed the held leads safely so none were lost (read the case study).

"Success" is not the same as working

A zap can run successfully and still do the wrong thing: create a duplicate, skip a step on a filter, or update the wrong record. Monitoring has to check outcomes, not just statuses.

How I monitor automations

  • Error paths: every important workflow has a branch that alerts a human on failure.
  • Outcome checks: a daily or weekly comparison, for example form submissions vs new CRM contacts.
  • Run logs: key runs logged to a sheet or database someone can read.
  • Fallbacks: a backup message or task when an AI or API step fails.

Testing habits that prevent problems

  1. Test every path with realistic data before going live.
  2. Retest after any change to a form, field or connected app.
  3. Document what each workflow does and who owns it.
